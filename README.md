# ValutaTrade Hub

Проект представляет собой консольное приложение для симуляции торговли валютами. Пользователь регистрируется, ведет портфель из фиатных и криптовалютных кошельков, покупает и продает единицы валют по текущему курсу и следит за самими курсами. Данные лежат в JSON-файлах рядом с проектом, поэтому база данных не нужна, и приложение работает сразу после установки зависимостей.

Работа разделена на две части, как предполагалось в задании. Core Service отвечает за пользователей, кошельки и интерфейс командной строки, Parser Service обращается к внешним API за актуальными курсами, приводит ответы к единому виду и складывает результат в кеш и в историю. Части не зависят друг от друга напрямую, ядро читает тот же файл `data/rates.json`, который пишет парсер, поэтому парсер можно не запускать вовсе и работать на кеше или на фиктивной таблице курсов.

## Установка

Потребуются Python 3.12 или новее и [uv](https://docs.astral.sh/uv/). Зависимости устанавливаются одной командой в корне проекта.

```bash
uv sync
```

Она создаст `.venv` и поставит `prettytable` и `requests`, `ruff` входит в dev-группу и нужен только для проверки стиля.

## Запуск

```bash
uv run project
```

Тот же результат дает `python main.py`, потому что в `pyproject.toml` объявлен скрипт `project`, а `main.py` вызывает `run()` из `cli/interface.py`. Приложение печатает приветствие и ждет команду в промпте `>`. Список команд доступен по `help`, выход по `exit` или `quit`. Пути к данным и логам считаются от корня проекта, поэтому запуск из другой папки не приводит к появлению лишних каталогов `data`.

## Команды

| Команда | Назначение |
|---|---|
| `register --username <name> --password <pw>` | создать пользователя, пароль не короче 4 символов |
| `login --username <name> --password <pw>` | войти, пользователь запоминается до конца сессии |
| `show-portfolio [--base <code>]` | кошельки и итоговая стоимость, по умолчанию в долларах |
| `buy --currency <code> --amount <number>` | купить указанное количество единиц валюты |
| `sell --currency <code> --amount <number>` | продать, с проверкой кошелька и остатка |
| `get-rate --from <code> --to <code>` | курс и обратный к нему курс |
| `update-rates [--source coingecko\|exchangerate]` | опросить источники курсов и обновить кеш |
| `show-rates [--currency CODE] [--top N] [--base CODE]` | таблица курсов из кеша |

Пароль в файлы не записывается, хранятся соль и хеш SHA-256, вычисленный от пароля с добавленной солью.

## Как считаются покупка и продажа

Выбрана упрощенная модель, в которой покупка увеличивает баланс только той валюты, которую покупают, и выводит стоимость покупки в долларах как оценочную, а продажа уменьшает баланс той же валюты и выводит оценочную выручку. Долларовый кошелек при этом не списывается и не пополняется, стартовый баланс в долларах не задается, потому что задание не предусматривает ни команды пополнения, ни начального остатка. Кошелек нужной валюты создается автоматически при первой покупке, а при продаже проверяются наличие кошелька и достаточность остатка.

## Кэш курсов и TTL

Ядро за курсами в интернет не ходит, оно читает `data/rates.json`, который наполняет Parser Service, и сверяет возраст снимка с настройкой `rates_ttl_seconds`. Три случая:

1. Снимок свежий, то есть с момента обновления прошло меньше TTL, и курс берется из кеша.

2. Снимок старше TTL, и курс все равно отдается пользователю, но к ответу добавляется предупреждение выполнить `update-rates`. Файл при этом не перезаписывается, потому что в нем могли лежать живые курсы парсера, и затирать их фиктивными значениями означало бы портить данные.

3. Кеша нет или в нем пусто, и тогда файл заполняется фиктивной таблицей `EXCHANGE_RATES` из `core/models.py` с источником `stub`, чтобы приложение оставалось работоспособным без парсера и без ключей.

Котировки хранятся парами к доллару, например `BTC_USD`. Конвертация идет через доллар делением одной котировки на другую, а обратный курс это обычное обратное число. Если нужной пары в кеше нет, команда сообщает, что курс недоступен, и просит повторить попытку позже.

## Parser Service и API-ключ

Parser Service опрашивает два источника, `CoinGeckoClient` отдает криптовалюты `BTC`, `ETH` и `SOL` и работает без регистрации, а `ExchangeRateApiClient` отдает фиатные `EUR`, `GBP` и `RUB`, для него нужен персональный ключ. Списки валют, эндпоинты и таймаут запроса в 10 секунд собраны в `parser_service/config.py`.

Запуск по требованию сделан командой `update-rates`, которая умеет опросить и один источник через `--source coingecko` или `--source exchangerate`. Отказоустойчивость настроена так, что сбой одного источника не отменяет обновление, курсы второго сохраняются, пары первого остаются в кеше со своим прежним временем обновления, а в конце печатается строка о завершении с ошибками. Каждая пара получает метку `updated_at` и имя источника, а история замеров дописывается в `data/exchange_rates.json` с идентификатором вида `BTC_USD_2025-10-13T18:02:11Z`.

```
> update-rates
INFO: Starting rates update...
INFO: Fetching from CoinGecko... OK (3 rates)
INFO: Fetching from ExchangeRate-API... OK (3 rates)
INFO: Writing 6 rates to data/rates.json...
Update successful. Total rates updated: 6. Last refresh: 2025-10-13T18:02:11Z
> show-rates --top 2
Rates from cache (updated at 2025-10-13T18:02:11Z):
+---------+----------+----------------------+
|   Пара  |     Курс |      Обновлено       |
+---------+----------+----------------------+
| BTC→USD | 77456.00 | 2025-10-13T18:02:11Z |
| ETH→USD |  2237.95 | 2025-10-13T18:02:11Z |
+---------+----------+----------------------+
```

Для автоматического запуска служит планировщик из `parser_service/scheduler.py`.

```python
from valutatrade_hub.parser_service.scheduler import create_default_scheduler

create_default_scheduler(3600).run_forever()
```

Ключ ExchangeRate-API передается через переменную окружения `EXCHANGERATE_API_KEY` и в репозиторий не попадает, файл `.env` тоже исключен из версионирования. В PowerShell ключ задается так:

```powershell
$env:EXCHANGERATE_API_KEY = "ваш_ключ"
uv run project
```

В командной строке Windows той же цели служит команда `set EXCHANGERATE_API_KEY=ваш_ключ`. Ключ подставляется в URL только на время запроса и не попадает в тексты ошибок и в журналы. Без ключа `update-rates` продолжает работать, криптовалюты обновляются, фиатные пары остаются в кеше с прежней меткой, а в `logs/parser.log` появляется запись о причине отказа.

## Конфигурация

Настройки приложения лежат в секции `[tool.valutatrade]` файла `pyproject.toml` и читаются синглтоном `SettingsLoader`. Пути разрешаются относительно корня проекта, а не текущего каталога.

| Ключ | Значение по умолчанию | Что задает |
|---|---|---|
| `data_dir` | `data` | каталог JSON-файлов |
| `rates_ttl_seconds` | `300` | возраст кеша курсов, после которого он считается устаревшим |
| `default_base_currency` | `USD` | валюта отчета по умолчанию для портфеля и сделок |
| `log_dir` | `logs` | каталог журналов |
| `log_level` | `INFO` | уровень журналов, для отладки ставят `DEBUG` |

## Данные и журналы

Файлы в `data/` меняются во время работы, и запись в них сделана атомарно. Данные сначала уходят во временный файл, а затем заменяют старый одним вызовом `os.replace`, поэтому процесс, прерванный на середине записи, не оставляет битый JSON.

Приложение ведет два журнала. В `logs/actions.log` пишет доменные операции декоратор `@log_action`, которым обернуты `buy` и `sell`, и в записи есть действие, идентификатор пользователя, валюта, сумма, курс и итог `OK` или `ERROR`, а при неудаче еще тип исключения и его текст. Второй журнал, `logs/parser.log`, ведет Parser Service, туда попадает каждый шаг обращения к каждому источнику. Оба журнала пишутся в UTF-8, а при достижении 1 МБ начинается ротация, поэтому рядом хранится по три файла.
